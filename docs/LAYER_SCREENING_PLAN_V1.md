# DCCF 逐层探针与双概念互补层实验计划

版本：v1（实验设计稿；尚未实现）  
适用范围：第二研究内容“对未见越狱攻击类型的双概念融合检测”。  
算法约定：以 `docs/METHOD.md` 与 `configs/qwen2_5_7b.json` 为准；本稿将逐层 MLP 预筛作为拟议扩展，不把它写成现有代码已经实现的步骤。

## 1. 实验目标与方法边界

本阶段只回答两个问题：

1. 哪些物理层的末 token 表征具有稳定的风险可分性，可以进入候选池？
2. 在候选层中，哪些层对风险概念与操纵概念分别保留了互补的检测信号？

Sentinel 的 P1 对每层独立训练一个两层 MLP，用正常与原始有害提示做探针；该探针测量的是该层对安全/有害输入的可分性，不等价于直接训练“越狱/非越狱”分类器。其 P4 再查看不同扰动策略下探针响应的层间行为，并据此去除冗余层。论文未报告可直接照搬的 AUROC 候选阈值。DCCF 保留“逐层探针预筛”的总体顺序，但第二阶段改为分别使用风险、操纵概念响应分析策略间差异，并用两分支的检测覆盖选择互补层；这属于 DCCF 的方法扩展，不应称为 Sentinel 原算法的复现。

本稿遵循当前 DCCF 定义：

- 风险概念：`B_i`（正常请求）对 `H_i`（原始有害请求）。
- 操纵概念：`H_i` 对 `J_{i,m}`（策略/攻击家族 `m` 下与 `H_i` 对应的越狱请求）。
- 全局风险标签：`B=0`，`H=1`，`J=1`。
- 仅在操纵分支的配对识别中，`H` 是 `J` 的参照负类；这不表示 `H` 是安全请求。

## 2. 数据与输入协议

### 2.1 固定表征

主干冻结为配置指定的 Qwen2.5-7B-Instruct。按聊天模板格式化完整输入并加入回答起始前缀，读取物理层 1–27 的末个有效 token 状态，每层维数 3584。提取时不生成回答、不做隐式截断。每条文本只提取一次，缓存应绑定模型 revision、tokenizer/chat template、层号、精度、文本哈希及提取协议哈希。

探针实验只读取这些冻结状态；不得在探针训练时微调主干。每个探针只读取一个物理层的向量。若做 MLP 输入标准化，只使用该折训练行估计均值和尺度，再原样用于验证行；常量维度尺度设为 1。标准化是探针预处理，不改动 DCCF 概念方向的既定构造。

### 2.2 项目内数据现状核查

截至 2026 年 11 月 5 日，仓库中的历史开发材料为：

| 角色 | 记录数 | 正常 | 原始有害 | 越狱 | 可用于本阶段的解释 |
|---|---:|---:|---:|---:|---|
| train | 866 | 400 | 266 | 200 | 开发拟合材料 |
| select | 439 | 279 | 120 | 40 | 开发筛选材料；越狱样本量较小 |
| calibrate | 140 | 140 | 0 | 0 | 安全阈值候选材料 |
| diagnose | 220 | 140 | 60 | 20 | 已暴露诊断材料 |

现有风险配对 200 条且全在 train；操纵配对为 train/select/diagnose 各 200/40/20 条。所有 1665 条历史记录的暴露标记是 `development_exposed`，标签状态是 `candidate_not_independently_validated`。因而，这些材料可以支持开发流程和代码调试，不能支持新的独立确认结论；`diagnose` 也不能改称确认集。操纵策略在 select 中的分母很小，按策略拆分时应同时报告样本数和区间，避免把低样本点估计当成稳定排序。

按当前家族归并规则，操纵配对的 train/select 数为：AutoDAN 36/6、DrAttack 17/3、SAA 53/10、PAIR+TAP 48/7、GCG+nanoGCG 46/14。select 中每家族只有 3–14 对，因此家族级 AUROC、阈值 TPR 与层排序均是探索性估计；不可据此声称某一攻击策略稳定地优于另一策略。矩阵横轴应明确写成归并后的攻击家族，除非数据另有独立审核的 `strategy_id`，不要把数据源方法名自动解释为单一包装操作。

JBB 试点目录目前有 372 条未分组候选材料（100 正常候选、100 有害候选、172 越狱候选），其中已审核记录为 0、已分配实验角色为 0。300 条风险配对只是候选建议，操纵映射仍待审核。因此该试点当前不能当作训练、筛层或确认材料。完成双人输入标签审核、配对映射审核、跨来源近重复审计及角色分组后，才可按冻结协议纳入。

执行任何模型运行前，先重新核验特征缓存行顺序、哈希和模板指纹；即使磁盘上存在历史状态缓存，也不能仅凭文件存在就视为匹配当前配置。

## 3. 阶段一：逐层 MLP 探针与候选池

### 3.1 探针任务

主分析沿用 Sentinel 的探针监督任务：以 `B=0`、`H=1` 训练每层一个独立探针。使用 train 中明确的 200 条风险配对端点（200 条 B 与 200 条 H），每个提示只出现一次。`J` 不作为该探针的训练标签；随后将探针应用到未参与探针拟合的 J 上，检验安全信号能否迁移到越狱输入。这样才能区分“层能分离普通有害提示”和“层能泛化识别越狱提示”两种结果。

这一主探针池产生风险可分候选集 `C_probe`，不应把它称为直接以越狱标签训练的攻击分类器。它可能漏掉“普通风险信号较弱、但擅长区分 J 与对应 H”的层。因此第二阶段必须分别评估风险和操纵两分支；并且在消融中比较全 27 层选层与 `C_probe` 限制后的选层。如果风险预筛确实排除了能提升操纵分支覆盖的层，报告为预筛局限；可另行验证一个候选扩展 `C_probe ∪ C_manip_probe`，其中 `C_manip_probe` 来自 train 内家族留出验证的 `H=0/J=1` MLP。这个双探针扩展是 DCCF 新变体，不能混称 Sentinel P1。

### 3.2 网络、优化与重复

每个物理层 `l∈{1,…,27}` 独立拟合相同结构的轻量 MLP：

\[
3584 \rightarrow 100 \xrightarrow{\mathrm{ReLU}} 2 \text{ logits}.
\]

用交叉熵训练，早停，最多 500 个 epoch；所有层使用相同的训练/验证划分、优化器设置、批量大小、种子和停止规则。100 个隐藏单元、交叉熵、早停与 500 epoch 上限参照 Sentinel 的实现描述。优化器、学习率、batch size、weight decay 与早停耐心值需在查看 select 结果前固定并写入配置；建议在 train 内以 `group_id` 为单位做 5 折，仅用于选定这些训练超参数和估计稳定性。不能随机拆开同一目标组中的 B/H/J。

探针至少用 5 个固定随机种子重复，固定相同的分组折；保存每层每折的预测分数和 checkpoint 哈希。先按折平均指标，再汇总折间均值、标准差和目标组 bootstrap 置信区间。不要把同一目标的多种包装当作独立样本来缩窄置信区间。

### 3.3 指标与候选准入

主要筛选指标为 AUROC。另报告 AUPRC、F1、准确率、召回率和低 FPR 下 TPR；F1 阈值只能由当前训练折确定，再原样应用到其验证折。F1 不作为独立的候选准入依据，因为它依赖类别比例和阈值。

候选准入使用 `B` 对 `H` 的组外 AUROC。为使“高 AUROC”可复现，DCCF 必须显式登记自己的 `tau_probe`；Sentinel 文中只给出符号阈值，没有公开数值。初始开发运行可预注册 `tau_probe=0.70`：层的 5 折×5 种子 AUROC 中位数须达到该值，按折汇总的最差 AUROC 不得低于 0.55，且至少 4/5 个种子的跨折平均 AUROC 大于 0.5。该规则是 DCCF 的工作门槛，不是 Sentinel 报告值，也不是最佳阈值的经验结论。查看 select 后不得降低门槛凑足候选层。

筛选输出分两栏：

- `C_probe`：达到预注册准入条件的探针候选层。
- `J_transfer`：对 select 中 J 的迁移检测结果，按攻击家族分别报告 AUROC、TPR@训练参考阈值与区间；不把它混入 B/H 探针的训练分数。

在现有 select 的 40 条 J 上，分家族统计可能非常不稳定。因此 `J_transfer` 用作描述性开发证据；若分家族样本过少，不用它设定准入线。待新数据完成审核和目标组划分后，再按相同规则做锁定验证。

若 `C_probe` 少于 2 层，按“探针阶段没有形成满足准入条件的候选集”报告并停止本轮 DCCF 双分支选层；不得临时降低 AUROC 门槛。若候选集过大，则全部交由阶段二的分支互补选择，不再按同一 select 集上的单层表现二次截断。

### 3.4 探针阶段产物

每轮需保存：数据清单哈希、训练/验证 group 清单、特征缓存哈希、逐层探针配置、随机种子、每折每层指标、预测分数、置信区间、`C_probe`、失败层及失败原因。探针模型只用于离线筛层与诊断；除非单独预注册比较，不把其 MLP 输出直接作为最终 DCCF 分类器。

## 4. 阶段二：风险与操纵概念响应矩阵

### 4.1 每折先重建概念参数

仅使用该折训练目标组构造两类配对方向：

\[
D_l^T[i]=h_l(H_i)-h_l(B_i),\qquad
D_l^J[i,m]=h_l(J_{i,m})-h_l(H_i).
\]

每层分别由风险配对和操纵配对估计训练参考方向及锚点，具体 SVD、符号约定、锚点和余弦读出沿用 `docs/METHOD.md`。对验证折的响应只做冻结读出，不重新拟合方向、锚点、标准化或阈值。

在 `C_probe` 的物理层上，分别计算风险读出 `c^T_l(x)` 和操纵读出 `c^J_l(x)`。每个验证单元按攻击家族 `m` 与目标组保存响应，不把来自同一 `H_i` 的多个 `J_{i,m}` 当成独立目标。

### 4.2 两张“策略 × 层”表

第一张是风险概念表。对每个候选层 `l` 与攻击家族 `m`，用风险读出评估 held-out `J_m` 的风险识别率：主要单元为在训练正常参考分布上冻结阈值后的 `TPR(J_m)`；同时给出 `AUROC(B vs J_m)`、`n_J`、正常控制数及目标组 bootstrap 区间。另设 `H` 原始有害基线行/列，不把 H 混入安全对照。该表表达“不同攻击家族的输入在该层是否仍保留可读的风险信号”。

第二张是操纵概念表。对每个 `l,m`，在精确匹配的 `(J_{i,m},H_i)` 上计算操纵读出的 `AUROC(H vs J_m)`、以训练 H 参考分布确定操作点后的 `TPR(J_m)`，以及配对响应差：

\[
\Delta^J_{l,m}=\operatorname{mean}_i\left[c^J_l(J_{i,m})-c^J_l(H_i)\right].
\]

同时报告配对差中位数、目标组 bootstrap 区间与 `n_pairs`。这一表回答“该层的操纵概念方向能否区分包装请求与对应原始有害目标，以及对不同策略的响应是否不同”。操纵分支的 H 参照误报率只是“误把原始有害目标判成操纵请求”的分支错误率，不能称为安全 FPR。

历史 select 的风险配对文件没有 H-B 配对，故风险矩阵只能按 select 中的 B 与 J 标签进行非配对风险检测评估，并需将目标领域/来源差异列为限制；它不能用于声称风险方向在同目标上作了配对复现。风险表的 `B` 与 `J_m` 并非同一个目标上的同包装四元组，所以 `AUROC(B vs J_m)` 是风险检测可分性，不是某个包装策略造成隐藏状态变化的因果效应。策略影响的配对解释主要来自 `J_m` 对应 `H_i` 的操纵矩阵。如果后续要把风险效应也解释为严格的包装效应，需要有同目标同包装的安全对照；当前三类数据定义本身不提供这种四元组，不能用跨目标 B 代替。

矩阵长表至少包含 `branch, physical_layer, attack_family, metric, estimate, ci_low, ci_high, n_goal_groups, n_prompts, threshold_source, split, fold_id`。输出热图时，风险 TPR、风险 AUROC、操纵 TPR、操纵 AUROC 和配对差分别成图，使用固定色标并在单元格标注样本数；不能把含义不同的量压成一个“敏感性”分数。

### 4.3 互补层选择规则

风险和操纵两分支独立选层，二者都只能从 `C_probe` 中选择。延续 `METHOD.md` 的内部攻击家族留出结构：每个折删除被留出家族的训练攻击与操纵配对，重估两个概念；只在对应 select 家族上计算响应。风险分支阈值以该折训练正常提示为参照，操纵分支阈值以该折训练的对应 H 为参照。安全输入始终单独标记，用于安全 FPR 控制。

互补性不等于某个层对单个策略有较大原始响应，也不等于层间余弦差异大。候选层应通过现有 `select_layers` 的分支效用选择：优先改善最差攻击组与宏平均攻击组覆盖、限制新增正常误报，并惩罚与已选层的响应冗余。两分支分别最多 4 层、最少 2 层；参数与物理层分组约定沿用当前配置。预先登记的现有 `auroc_min=0.55` 是概念分支候选门槛，不可与新增的 `tau_probe` 混为一个阈值。

落地实现时需把阶段一候选掩码传给两次分支选择；目前 `select_layers` 接收传入层轴并无 MLP 候选生成步骤。候选少于分支最小预算时显式失败，不回填候选池之外的层。两分支最终层集合可重叠；融合层集合为其并集，但物理层的分组惩罚仍按同一层合并，遵循当前 METHOD。

## 5. 数据划分、统计与泄漏控制

### 5.1 内部开发与确认评估

当前历史数据仅适用于开发分析。可以使用 train 拟合探针/概念，并用 select 构造内部家族留出矩阵与选层；但所有基于这些材料选出的 `C_probe` 和概念层集合都属于模型选择结果。`diagnose` 只在本轮规则冻结后做开发诊断，不能用于改门槛后再声称独立结果。现有 calibrate 的 140 条记录虽为正常候选且单独分区，但 `development_exposed` 状态仍不能支持独立确认或泛化误报保证。

确认阶段必须新增未暴露的目标组，并先完成人工标签、配对、重复样本和来源谱系审核。确认材料需在探针结构、`tau_probe`、概念配置、候选层名单、分支选择参数、融合器及阈值规则全部冻结后只运行一次。留出攻击家族的 J、其精确 H 端点及同目标衍生记录不得进入探针监督、概念拟合、锚点、标准化、层选择、融合或阈值拟合。

若要主张“未见攻击类型”，需以攻击家族留出为外层单位，并在外层内重新执行探针筛层和双概念选层；同一外层测试家族不能参与任何候选准入或调参。当前内部家族折可用于开发层选择，但同一批 select 又用于选层时，其得分不是独立性能估计。外层确认结果须按家族宏平均，并用目标组作为 bootstrap 单位。

### 5.2 统计单位和报告指标

独立统计单位优先使用 `group_id`/目标组。报告每家族原始分母，使用目标组 bootstrap 给出 95% 区间。候选层与互补层的主比较指标为：

- 每分支单层与所选组合的 AUROC；
- 固定训练参考阈值下的总体及逐攻击组 TPR、最差组 TPR；
- 正常控制 FPR（宏平均与总体均报告）；
- 选层数量、两分支层集合交集、与全 27 层的响应相关性；
- 不同目标组 bootstrap/探针随机种子下候选层与最终层集合的稳定率；
- 推理路径、特征缓存和检测头参数量。当前完整主干前向仍执行，不能把层筛选结果表述为已经减少主干计算。

不要把目标组内多个包装、同一 H 的多种攻击、不同随机种子的探针模型或 27 个物理层计为独立样本。

## 6. 必要对照与消融

为确定两阶段设计是否提供增益，至少预注册以下对照：

1. **全层对照：** 不经过 MLP 预筛，27 层直接执行两分支互补选择。
2. **探针候选对照：** 限定在 `C_probe` 后分别执行两分支互补选择。
3. **单层对照：** 每个分支仅保留该分支内部验证 AUROC 最佳层。
4. **单概念对照：** 仅风险分支、仅操纵分支及双分支融合。
5. **互补规则对照：** DCCF 的分支覆盖效用与 Sentinel 式探针响应相关性贪心筛层比较；层数预算保持一致。
6. **候选集扩展对照：** 风险探针候选集 `C_probe` 与 `C_probe ∪ C_manip_probe` 比较；操纵探针必须采用按攻击家族留出的验证，避免将同一包装家族同时用于训练和筛选。
7. **探针标签对照：** 主分析的 B/H 探针与训练标签扩展为 B/(H+J) 的消融比较；该消融训练时见到 J，不能作为“未见家族”结果。
8. **随机层对照：** 按相同候选数和分支预算随机抽层，重复抽样形成分布，不挑选单个不利随机样本作为基线。

所有方法使用同一冻结主干、同一文本和分组、相同阈值预算与确认集；任何超参数在确认集上调过后，原确认集立即转为开发数据。

## 7. 执行顺序与停止条件

1. **数据闸门：** 审查候选标签与精确配对；锁定 goal group、策略家族及 train/select/confirm 清单；确认文本哈希与来源记录。
2. **表征闸门：** 重核冻结模型、模板、层号和状态缓存指纹；修正任何错位或过期缓存。
3. **预注册：** 冻结 MLP 结构、优化器、五折分组、种子、`tau_probe`、指标、矩阵定义、分支选择预算、消融和失败报告规则。
4. **阶段一：** 运行 27 个逐层探针，导出每层跨折性能、候选名单及对 J 的迁移诊断。
5. **阶段二：** 只在候选层上用训练折重建两概念并输出两张长表/热图；按预设效用分支独立选层。
6. **锁定评估：** 先冻结模型文件和配置哈希，再一次性运行独立确认；若确认数据尚未准备好，则将结果标为开发性，不改用 diagnose 代替。

以下情况按失败或证据不足报告，不事后修规则：候选层少于 2 层；任一分支达到不了最小层数；部分攻击家族有效配对不足；层集合对目标组或种子高度不稳定；跨家族性能区间过宽；或数据标签/映射审核未通过。可据此启动下一轮开发，但该轮数据须标记为已暴露。

## 8. 本轮建议结论

先用现有历史状态做一次严格标记为“开发诊断”的复现性试跑，确认 27 层 MLP 指标流水线与两张策略×层表可以产出；该运行不能支撑确认性性能结论。JBB 试点完成双人审核和分组后再作为新开发/筛选材料。只有另有未暴露目标组与外层留出家族后，才能评估最终候选筛层及双概念互补选择是否提升了未见攻击家族检测。
